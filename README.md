# zed-markdown-swift

Zed's GPUI Markdown view, embedded in a SwiftUI app as an `NSView`-backed component.

Zed's dependency tree is huge, so this lives in its own repository instead of inside a larger app,
where it would dominate build times. The first build compiles about 800 Rust crates and produces a
multi-GB debug static library.

```swift
import ZedGPUI

ZedMarkdownView(markdown: text, baseURL: folderURL)
  .zedOnOpenURL { url in print(url) }
```

The view follows the SwiftUI color scheme (Zed's One Light / One Dark). The theme is global to the
embedded GPUI app.

## Run the demo

```bash
mise run run:app
```

The demo opens `.md` files (toolbar, drag and drop, or `--open <path>`), reloads on change, and takes `--dark`.

## Layout

| Path | What |
| ---- | ---- |
| `packages/gpui_macos` | Zed's `gpui_macos` with a hosted `NSView` mode; see its [UPSTREAM.md](packages/gpui_macos/UPSTREAM.md) |
| `packages/zed-gpui-c-api` | Static library with the C interface in `include/zed_gpui.h` |
| `Sources/ZedGPUI` | `ZedMarkdownView` (`NSViewRepresentable`) |
| `Demo/ZedMarkdownPreview` | Demo app |
| `Cargo.toml` | Generated by `scripts/sync_zed_workspace.py` from a Zed checkout; Zed crates are git deps pinned to one revision |

## How the embedding works

GPUI normally owns `NSApplication` and creates its own `NSWindow`s. The modified `gpui_macos` adds
`MacPlatform::new_hosted()`, which leaves the run loop to SwiftUI, and `set_next_window_host_view`,
which makes the next `open_window` add GPUI's `GPUIView` as a subview of a SwiftUI-owned `NSView`.
The host window's key, occlusion and screen notifications are forwarded to GPUI.

## Update Zed

```bash
python3 scripts/sync_zed_workspace.py /path/to/zed
```

Then re-copy `crates/gpui_macos` and re-apply the hosted-mode changes listed in its UPSTREAM.md.
